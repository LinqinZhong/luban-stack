# 项目怎么组织

一个业务项目就是一个文件夹。打开时必须能识别为合法项目（配置文件存在且有效）。

## 你要关心的几块

| 部分 | 用途 |
|------|------|
| 项目配置 | 名称、画布宽度、入口页、运行环境（如小程序）、接口基址等 |
| 页面 | 可路由打开的界面 |
| 组件 | 可复用的界面块，被页面或其他组件引用 |
| 服务 | 后端模块（接口、业务、数据），前端通过绑定或调用使用 |
| 类型 | 共享数据结构，给数据、属性、接口对齐用 |
| 主题与资源 | 命名颜色、图标、对象存储、数据库连接等 |
| 构建方案 | 导出/打包时包含哪些页面与服务 |

## 使用原则

1. **先定入口页**，再长出其它页面与组件。  
2. **能复用的 UI 做成组件**，页面只负责编排与路由级数据。  
3. **跨页面稳定的数据形状放进类型库**，避免各处各写一套。  
4. **后端能力放在服务里**，前端只绑「调哪个接口、入参从哪来」，不要在界面里拼 SQL。  
5. 磁盘上每个页面/组件/服务都有稳定 id（文件夹名或配置里的 id）；绑定引用的是 id，不是显示名称。

## 页面与组件的分工

- **页面**：有路由、可接收查询参数、可配置状态栏等壳层信息。  
- **组件**：无独立路由；通过属性接收数据、通过事件/暴露方法与父级协作。

两者内部结构相同：界面 + 数据池 + 方法（+ 可选生命周期）。
