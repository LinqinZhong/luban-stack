# 推荐怎么搭

抽象流程，不依赖具体业务。

## 1. 立项目骨架

定入口页、画布与目标端、主题色与图标，必要时先建好类型与后端模块。

## 2. 先画主路径页面

用布局控件搭结构 → 数据池建状态 → 关键绑定到界面 → 点击跳到下一页。  
主路径通了再补边缘状态（空、错、加载中）。

## 3. 重复块抽组件

卡片、列表外壳、选择器等下沉为组件：属性进、事件出；需要命令式操作再暴露方法。

## 4. 接数据

- 进页即显：数据池绑接口。  
- 用户触发或分页：方法里调「接口型属性」或编排结果。  
- 写入/副作用：走服务业务能力或输出节点。

## 5. 打磨体验

条件显隐、动态样式、滚动联动、状态栏与主题统一；复杂分支进方法与生命周期。

## 6. 导出前检查

入口是否正确、接口基址是否指向目标环境、构建方案是否包含所需页面与服务。

---

记住：**界面负责呈现与触发，数据池负责状态，方法负责过程，服务负责远程与持久。** 四层职责清晰，项目就好维护。
