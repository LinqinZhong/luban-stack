# 前端怎么用后端服务

服务侧提供 HTTP 接口与业务能力；前端不直接操作数据库，只声明「调谁、参数从哪来、结果放哪」。

## 三种常见接法

### 1. 数据池绑接口

字段声明绑定某个 API：入参可来自路由参数或其它字段；返回经解析后写入该字段。  
适合：进页自动加载详情、配置类数据。

### 2. 组件属性是「可调用的接口」

父级把某个 API 配进组件属性；组件方法在需要时调用（例如分页加载更多）。  
适合：可复用的分页器、搜索列表等把「怎么展示」与「哪个接口」解耦。

### 3. 业务流里的输入 / 输出

在服务编排里，节点可以调本模块业务/数据方法，也可以走「网络」请求外部 HTTP。  
- 需要结果再继续：用输入并等待。  
- 只投递不等待：用输出异步发出。

## 使用建议

1. 先在服务里定义稳定接口，再在页面/组件绑定，避免前端先写死后端改路径。  
2. 列表分页、筛选条件变化频繁时，用「可调用接口属性 + 方法」比纯自动字段更灵活。  
3. 跨系统回调、Webhook 等放服务编排的网络节点，不要堆在页面方法里。  
4. 接口基址在项目配置里按环境/模块配置，业务绑定只记服务与接口标识。
