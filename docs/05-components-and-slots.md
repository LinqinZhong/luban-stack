# 组件与插槽怎么用

组件是可复用的界面单元：有独立界面、数据与方法，通过属性接收外部输入，通过事件或暴露方法与外部协作。

## 何时抽组件

- 多处出现同一块 UI 与行为（卡片、标题栏、分页器、选择器）。  
- 需要独立状态机（下拉刷新、内部页码），又不想污染页面数据池。  
- 希望父级只关心「给我数据和回调」，不关心内部结构。

## 对外三种口

| 口 | 方向 | 用途 |
|----|------|------|
| 属性（props） | 父 → 子 | 传入文案、列表、开关、接口能力等 |
| 事件 | 子 → 父 | 通知「点了某项」「要跳转」等，由父级决定怎么办 |
| 暴露方法 | 父 → 子（调用） | 父级通过引用主动调用，如重置、打开弹层 |

属性可标为「可回写」：子组件在逻辑里更新后，父级绑定的数据会跟着变（适合列表、loading）。

## 插槽

组件内部预留「洞」；父级引用组件时，把自己的控件树塞进指定插槽。  
适合：分页器外框固定，列表项/页头由使用方决定。

## 使用建议

1. 属性尽量少而稳：必要数据 + 必要回调/事件。  
2. 导航、全局提示优先放页面；组件通过事件把意图抛上去。  
3. 需要父级命令式操作时，再暴露方法，并用数据池「引用」指向该组件实例。  
4. 单独调试组件时，用调试属性填假数据，不依赖真实页面。
